Nota de revisión KAIRUM

Cómo interpretar esta respuesta

Respuesta observada en esta muestra. Provincia NET/NET Pagos, Banco Provincia y Cuenta DNI cumplen roles diferentes. El estudio contempla la empresa que recauda y el comercio que busca ser punto de pago; sus requisitos y condiciones no se trasladan entre recorridos. Una oferta integrable o un portal autenticado no prueban públicamente sus endpoints, formato de conciliación, sandbox, SLA ni una implementación para cualquier cliente.

Para una empresa con software propio, el canal oficial principal es ARCA (ex AFIP), porque allí se autoriza fiscalmente la factura. ARCA distingue: - **Web Service de Factura Electrónica (WSFEv1):** opción general para solicitar CAE e integrar un sistema propio. - **WSMTXCA:** alternativa para comprobantes con mayor detalle por ítem y operaciones específicas. - **WSFEXv1:** facturación electrónica de exportación. - Otros servicios sectoriales —por ejemplo, seguros de caución o bonos fiscales— aparecen en el [catálogo oficial de Web Services](https://www.arca.gob.ar/ws/documentacion/catalogo.asp). La página oficial de [Factura Electrónica por Web Service](https://arca.gob.ar/fe/ayuda/webservice.asp) publica los manuales, especificaciones, preguntas frecuentes y versiones vigentes. Conviene verificar allí la versión antes de desarrollar, porque los manuales pueden actualizarse. Pasos documentados para probar una integración: 1. Revisar el manual del Web Service aplicable y su WSDL. 2. Solicitar/adherir el servicio **WSASS** desde el Administrador de Relaciones con Clave Fiscal. 3. Generar un certificado digital para homologación. 4. Asociarlo al Web Service de negocio. 5. Desarrollar y probar contra el ambiente de testing. 6. Para producción, gestionar el certificado mediante [Administración de Certificados Digitales](https://www.arca.gob.ar/ws/documentacion/certificados.asp) y delegar/asociar el servicio desde Clave Fiscal. El flujo de autenticación se documenta en [WSAA](https://www.arca.gob.ar/ws/documentacion/wsaa.asp). Además, ARCA exige gestionar un **punto de venta específico para Web Service**, mantener la numeración correlativa y solicitar autorización por cada comprobante. Esto está confirmado en la sección [Emisión y autorización](https://www.arca.gob.ar/fe/emision-autorizacion/solicitud-autorizacion.asp). Lo que requiere consulta específica: - Qué Web Service corresponde según actividad, tipo de comprobante, régimen impositivo y nivel de detalle. - Reglas funcionales, percepciones, notas de crédito/débito, CAEA, moneda y datos obligatorios. - Habilitación efectiva de cada punto de venta y paso de homologación a producción. Para consultas, ARCA indica el [Micrositio de atención](https://www.arca.gob.ar/fe/ayuda/entorno-prueba.asp); algunas modalidades también tienen canales técnicos o funcionales específicos publicados en sus manuales. Esto no cubre la integración con una pasarela de pagos: el Web Service fiscal autoriza comprobantes, no procesa el cobro.
